Tanggal: 2026-10-20
Metode: `brainstorm` (gate) + `brainstorm-ideas-new` + `idea-refine` + `identify-assumptions-new` +
`pre-mortem` + `strategy-red-team` + `job-stories`, dijalankan lewat `sequential-thinking` MCP.

## Langkah 1 - Framing

**Masalah (bukan fitur):** mod `soulland` saat ini punya sistem kultivasi yang bekerja, tapi
*alasannya* hilang. Pemain memasang mod ini karena avid novelnya, lalu menemukan:

1. Martial soul yang jadi identitas pemain hanya tampil sebagai teks di chat. Tidak ada yang
   bisa dilihat. Padahal di novel, martial soul adalah parasitic yang melayang di belakang
   pemiliknya dan ikut bertarung.
2. Semua skill terasa sama secara visual. Satu `switch` giant di `SkillHandler` memilih efek
   vanilla (`EXPLOSION`, `FLAME`, `HEART`), jadi 20 skill terlihat seperti 4.
3. Setiap martial soul cuma punya 2 skill. Di novel, soul ikatan adalah inti pengalaman, dan
   jumlah skill menentukan kedalaman identitas soul.
4. Aset item masih placeholder. `spirit_ring_*.json` menunjuk `minecraft:item/ender_pearl`.
   Empat spirit ring terlihat seperti permen ender pearl abu-abu. Tidak ada assets sama sekali
   untuk soul, partikel, atau GUI.

**User utama:** pemain Minecraft (singleplayer atau server) yang penggemar Soul Land, sudah
terpasang Forge 1.20.1, dan bermain lewat "dunia Benua Douluo" bareng teman. Skill teknis: menengah.
Mereka memasang modpack, bukan satu jar, jadi ekspektasinya "modpack besar": banyak
isi, lengkap, dan terasa finished. Untuk dianggap "besar", yang pertama mereka cek adalah *tampilan*.

**Success criteria (verifiable):**
1. Pemain bisa melihat martial soul-nya di dunia (bukan cuma di chat) dalam <= 3 detik setelah
   menekan 1 tombol, dan adept melihatnya di kartu GUI dengan portrait yang relevan.
2. Tidak ada 2 skill yang terlihat identik. Setiap skill punya signature visual sendiri
   (bentuk, warna, partikel, suara, dan/atau efek kamera).
3. Setiap martial soul punya >= 5 skill yang terbuka secara progresif mengikuti spirit ring.
4. Tidak ada item yang memakai texture placeholder vanilla.
5. `gradle build` lulus dan CI (build + boot server Forge) hijau.

**Bukan scope (Not Doing) - eksplisit:**
- Custom mob model 3D. Soul beast memakai mob vanilla dengan penamaan tier + stat, bukan model baru.
- Dimensi baru, biome baru, struktur dunia.
- Audio SFX custom (mp3/wav). Semua suara dari `SoundEvents` vanilla.
- Config screen, texture packer, resource pack, shader.
- Multiplayer rank/sect PvP, guild, ekonomi.

## Langkah 2 - Divergensi: 3 pendekatan

### A. Solusi inti (bagian terbesar dari usaha): "60 skill bespoke"

**Ide:** setiap skill punya kelas handler sendiri dengan efek partikel, animasi, dan entity
sendiri.

- **Kelebihan:** kualitas per skill maksimum, tiap skill benar-benar unik.
- **Kekurangan:** 60 kelas + 60 renderer = ribuan baris yang tidak pernah diuji client,
  konsumsi konteks luar biasa, dan hasil akhirnya *generic* karena copy-paste struktur.
- **Risiko terbesar:** scope meledak, tidak pernah sampai selesai, tidak ada yang terverifikasi.

### B. Solusi inti: "arketipe VFX"

**Ide:** satu deskriptor visual per skill (shape + warna + skala + partikel + suara + shake),
enam arketipe render: `SPHERE`, `LINE`, `CONE`, `RING`, `PLANE`, `COLUMN`.

- **Kelebihan:** 60 skill jadi 60 baris data, signature unik tetap mungkin karena parameter
  warna/skala/count berbeda per skill. Rendering terpusat, mudah di-debug, murah.
- **Kekurangan:** tanpa bentuk yang benar-benar custom, ada batas "wow" untuk teknik ikonik
  (gelombang harimau, meteor phoenix).
- **Risiko terbesar:** terasa repetitif kalau warna jadi satu-satunya pembeda.

### C. Solusi inti: "hybrid" (DIPILIH)

**Ide:** arketipe untuk semua 60 skill + 8 sampai 10 **entity VFX ikonik** untuk teknik yang
membedakan soul (gelombang cahaya White Tiger, meteor Phoenix, sulur Blue Silver, retakan
tanah Clear Sky Hammer, aura Putar Pagoda Tujuh).

- **Kelebihan:** setiap skill punya signature, teknik ikonik punya bentuknya sendiri, jumlah
  kelas renderable terkendali (~15 bukan 60).
- **Kekurangan:** butuh dua jalur rendering (partikel arketipe + entity custom), sedikit lebih
  banyak plumbing.
- **Risiko terbesar:** scope creep di bagian entity VFX.

**Kenapa C menang:** B sendirian menghasilkan "60 skill yang berwarna beda" (persis println
"warna jadi satu-satunya pembeda" di B). A sendirian tidak akan pernah selesai di satu sesi.
C memberi batas kelas yang realistis (15) sambil mempertahankan signature unik, dan crucially
*semua* skill punya visual, bukan cuma 10oyer.

### Diverensi 2: "menampilkan martial soul"

| Opsi | Isi | Nilai |
|---|---|---|
| A. Soul Card GUI (tekan J) | 3 tab: Soul / Skills / Rings, portrait besar, status lock | Murah, andal, jelas "menampilkan" |
| B. Companion entity (tekan V) | Entitas yang melayang mengorbit, sprite billboard per soul, echo saat skill | Paling "merasa seperti novel" |
| C. Aura + ikon | Aura di pemain, ikon di HUD | Selalu aktif,Zpengikat identitas |

**Pilihan: A + B + C berlapis.** Masing-masing punya satu perilaku nyata, tidak ada kontrol mati.
A untuk "pamer", B untuk "hidup di dunia", C untuk "selalu terlihat".

## Langkah 2b - Mekanisme & sistem

### Alur data skill (server authoritative)

```
tekan tombol skill (client)
  -> ActivateSkillPacket(slot)          [C2S]
  -> SkillHandler.activate(player, slot)
       -> validasi:bangkit, soul ada, skill ada, ring cukup, cooldown, spirit power cukup
       -> SkillEffect.execute(player, skill)      [mekanik: damage/efek/buff]
       -> SkillFx.play(level, player, skill.visual)  [visual: partikel arketipe + entity VFX ikonik]
       -> VisualFxPacket(shake, flash)            [S2C] -> ClientFx
       -> cooldown + energi dikurangi, disinkronkan
```

### State & transisi

| State | Pemilik | Transisi | Gagal di tengah? |
|---|---|---|---|
| `awakened` | capability pemain | login pertama -> roll soul | tidak ada, roll selalu berhasil |
| `rings` 0..9 | capability | absorbent ring (butuh level & slots) | check dulu, baru kurangi stack |
| `cooldownUntil` per skill | capability map | cast -> now+cooldown | jam server, konsisten antar client |
| `sect` (null / shrek / tang / starluo / qibao) | capability | `/sect choose` | hanya boleh 1x (atau ganti dgn token) |
| `evolutionStage` 0..2 | capability | pakai `evolution_core` + esensi | check stage & bahan sebelum konsumsi |
| `meditating` | server tick | tahan tombol C & diam | cancel kalau gerak, timer reset |
| `summoned` | entity presence | tekan V -> spawn/despawn entity | idempoten, cek existing |

### Kontrak antarmuka

| Packet | Arah | Isi | Catatan |
|---|---|---|---|
| `ActivateSkillPacket(slot)` | C2S | int slot 0..4 | validasi penuh di server |
| `SyncCultivationPacket` | S2C | level, xp, rings, energy, soulId, sect, evolution | single source HUD |
| `VisualFxPacket` | S2C | shake(float), flash(int ARGB), duration | client-only, murni kosmetik |
| `OpenSoulCardPacket` | S2C | void | server mengirim -> client membuka GUI |

Tidak ada API eksternal. Tidak ada deps jaringan. Tidak ada secret.

### Model data

```
MartialSoul(id, name, owner, type, rarity, weight, description,
            element, color, portrait, evolutionId, skills[5])
SkillDef(id, name, description, energyCost, cooldownTicks, ringsRequired,
         target, visual, damage, effect, effectTicks, effectAmplifier, radius)
SkillVisual(shape, color, color2, size, count, sound, shake, flash)
```

`ICultivation` bertambah: `sect`, `evolutionStage`, `meditationTicks`, `summoned`.

### Keamanan

- Semua efek skill dijalankan di server. Client hanya mengirim *permintaan*, tidak pernah
 nymyen damage/efek.
- Energi, cooldown, dan syarat ring divalidasi ulang di server sebelum eksekusi.
- `VisualFxPacket` hanya data visual (angka), tidak bisa mengubah state pemain.
- Command admin (`/cultivation set`) tetap butuh permission 2.
- `martialsoul reroll` tetap Creative-only, tidak berubah.

### Kegagalan

| Gagal | Gejala ke user | Consistensi |
|---|---|---|
| Energi kurang | "Spirit Power tidak cukup (butuh X)" | energi tidak dikurangi |
| Cooldown | "Skill masih cooldown: N detik" | cooldown tidak diubah |
| Ring kurang | "Skill terkunci, butuh N spirit ring" | tidak ada efek |
| Target tidak ada | "Tidak ada musuh di jangkauan" | energi TIDAK dikurangi (kembalikan) |
| Skill id tidak dikenal | fallback: pesan generic, log warn | tidak crash |

Kasus "tidak ada musuh" adalah satu-satunya yang harus mengembalikan energi, karena skill
gagal total. Implementasi: `execute()` mengembalikan `boolean sukses`; hanya kalau sukses
energi dipotong.

## Langkah 3 - Rencana anti-AI-slop

**Identitas:** "Artefak kultivasi kuno Benua Douluo". Bukan "UI gelap dengan neon ungu".
Referensi visual: lencana geopolitik Tionghoa, giok, sutra, dan ukiran katana, bukan sci-fi.

**Sistem visual (token):**
- Palet inti 3 warna + 1 aksen:
  - `Soul Jade` `#4FC08D` (hijau giok) = kanal utama, spirit power, hal yang "hidup".
  - `Imperial Gold` `#E8C46A` = peringkat, achievement, hal yang "didapai".
  - `Ink Black` `#14161A` = bidang, tekstur, kedalaman.
  - Aksen tunggal: `Crimson Soul` `#D8442F` = bahaya, damage, boss.
  - Biru ungu ungu `#6A3FD1` HANYA untuk evolusi/legendaris (rare, jadi 이벤 langka).
- Type scale Minecraft: 1 ukuran (font vanilla). Tidak ada font custom, tidak ada "terminal".
- Radius: 0 untuk texture pixel-art, 2px untuk panel GUI. Tidak ada pill.
- Texture: hanya pixel art 16x16 dan 32x32 yang digambar tangan, tanpa gradient.

**Pola interaksi:**
- HUD: kiri atas = portret soul + 5 slot skill bernomor (abu = terkunci, warna skill = siap,
  sapuan gelap = cooldown). Kiri bawah = bar spirit power. Detail = tekan `J`.
- Soul Card GUI: portrait besar di kiri, 3 tab di kanan. Tab aktif punya garis bawah warna
  aksen, bukan capsule.
- Empty state: kartu soul tanpa soul (belum bangkit) menampilkan "Belum ada martial soul"
  dengan instruksi, bukan panel kosong.
- Loading state: tidak ada network fetch, jadi tidak ada loading state yang perlu.
- Error state: skill gagal = chat message spesifik (warna merah) + tidak ada efek visual,
  supaya user tahu itu bukan bug.

**Microcopy tone:** Bahasa Indonesia ringkas, referensikan istilah novel (spirit ring,
martial soul, soul beast). Contoh: "Spirit Ring 10.000 tahun diserap. Cincin kedua."
dan "Skill terkunci. Butuh 3 spirit ring."

**Checklist larangan:**
- Tidak ada emoji sebagai ikon di GUI/HUD (pakai texture pixel art).
- Tidak ada teks placeholder ("Lorem ipsum", "Coming soon", "TODO").
- Tidak ada gradient ungu-biru.
- Tidak ada kartu rounded seragam: kartu soul punya portrait besar, daftar skill pakai baris
  dengan ikon pixel art.
- Eyebrow badge di atas heading: tidak ada. Langsung ke isi.
- Angka tanpa sumber: semua angka (level, ring, cooldown) dari state nyata.

**Rencana visual motion:** dials ENERGY 2 / RHYTHM 2 / MOTION 2 (dunia game, bukan landing page).
Motion: shake kamera + flash hanya saat skill besar, echo companion saat skill ikonik.
Tidak ada animasi loop tanpa trigger.

## Langkah 4 - Rencana kebenaran

**Edge case yang diuji:**
1. Pemain belum bangkit (soul null) -> semua aksi skill no-op, GUI menampilkan empty state.
2. Skill di slot yang tidak ada (slot >= jumlah skill) -> pesan, tidak crash.
3. Energi pelarutan (energi < cost) -> skill ditolak, energi tidak jadi negatif.
4. Cooldown dipanggil ulang spam (double-click) -> hanya satu eksekusi per window cooldown.
5. Effek pada entity yang mati di tengah tick -> cek `isAlive()` sebelum apply.
6. Dua pemain cast skill bersamaan -> tidak ada state global yang dibagi, semua per-pemain.
7. Server dedicated tanpa client mod -> tidak boleh crash (semua class client di-guard `Dist.CLIENT`).
8. Regex/unicode di nama pemain -> pesan pakai `Component` API, bukan string concat mentah.
9. Item stack deplete (creative mode) -> `shrink` hanya kalau bukan creative.
10. World unchunk / entity di chunk lain -> target search dibatasi radius, bukan global scan.

**Failure mode dependency:** tidak ada dependency eksternal. Semua aset di dalam jar.

**Pre-mortem (ringkas):**
- *Tiger*: compile gagal karena API 1.20.1 beda dari asumsi. Pencegahan: compile-check berkala,
  tulang punggung rendering pakai `EntityRenderer` + `RenderType` + `GuiGraphics` (API paling
  stabil), custom particle hanya bonus opsional.
- *Tiger*: 60 skill tapi hanya 2 outcome visual. Pencegahan: signature wajib per skill
  (shape + warna + ukuran + partikel + suara), plus companion echo.
- *Tiger*: push kode rusak. Pencegahan: compile check lokal sebelum push + CI sebagai gerbang.

**Performa:** partikel dikuantitaskan per archetype (maks 120 per call), entity VFX punya lifespan
<= 60 tick dan self-remove, `sendParticles` hanya ke player terdekat (radius 64) untuk efek
lokal, efek area besar memakai `sendParticles` dengan `skipOutOfRange`.

## Asumsi berisiko (tidak bisa diverifikasi sekarang)

1. **Asumsi:** potret soul 16x16 akan terbaca jelas sebagai "martial soul" dan bukan noise.
   Mitigasi: 11 kelompok dengan 3-8 siluet berbeda, silhouette kuat (bentuk utama terbaca
   hitam-putih), dan warna elemen sebagai identitas.
2. **Asumsi:** 5 skill per soul dengan gate 1/2/3/5/7 ring memberi progresi yang terasa.
   Mitigasi: gate yang bisa diubah Constants satu file.
3. **Asumsi:** pemain menganggap companion yang melayang sebagai representasi martial soul.
   Mitigasi: 3 mode (ring/texture/entity) + GUI portrait sebagai backup utama.
4. **Asumsi:** sistem sekte tidak bertentangan dengan progresi. Mitigasi: sekte pure bonus, nol penalti,
   bisa diganti di Creative.
