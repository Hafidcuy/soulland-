# Soul Land Mod v1.1 "Manifestation" — Blueprint P1/P2

Rancangan ringkas sebelum menulis kode. Setiap keputusan visual/arsitektural
disini disertai alasannya (aturan R-31: setiap keputusan harus bisa dijelaskan
dalam satu baris).

## 0. Design Read

> Reading this as: **layar upacara kebangkitan dalam game**, untuk **pemain
> Minecraft yang baru masuk dunia**, dalam **gaya "ink-and-jade ritual"**
> (tinta pekat, jade sebagai aksen tunggal, teks seperti kertasRice), dial
> **ENERGY 2 / RHYTHM 2 / MOTION 1**.

- ENERGY 2: momen ini terasa berat (upacara), tapi tetap berupa menu game, bukan
  halaman pemasaran.
- RHYTHM 2: tiga zona dengan komposisi berbeda (tab kategori → daftar soul →
  panel preview), bukan grid kartu seragam.
- MOTION 1: chrome GUI statis. Animasi hanya hover/seleksi. Animasi manifestasi
  hidup di ruang dunia, bukan chrome UI.

## 1. F1 — Halo Spirit Ring

### Opsi yang dipertimbangkan (divergent)

1. `RenderPlayerEvent.Post` + quad kustom per ring, billboard ke kamera.
2. `RenderLevelStageEvent` (AFTER_TRANSLUCENT) menggambar ring di ruang dunia.
3. `ItemRenderer.renderStatic` dengan item `spirit_ring_*` yang sudah ada.
4. Entity client-side khusus (mis. `SoulHaloEntity`).
5. Satu quad besar berisi 9 ring yang di-bake jadi satu tekstur.
6. Partikel server (tidak bisa berbentuk cakram datar).
7. Quad kustom dengan satu sprite ring putih + tint warna per umur.

### SCAMPER pada 3 ide terpilih

**Ide 1 (quad kustom + tint):**
- *Substitute*: satu sprite ring putih, warna per umur lewat tint vertex.
- *Combine*: gabungkan halo + manifestasi ke satu event render.
- *Modify*: billboard horizontal saja, bukan billboard penuh.
- *Eliminate*: hilangkan rotasi per ring (rings diam) →.lifecycle hilang.
- *Reverse*: ring terbaru paling dekat kamera.

**Ide 2 (pakai item model spirit ring yang sudah ada):**
- *Substitute*: ganti sprite item jadi PNG sendiri.
- *Combine*: pakai warna rarity item sebagai warna ring.
- *Modify*: item model jadi `item/generated` dengan tekstur 32x32.
- *Eliminate*: hapus orientasi horizontal (semua tegak).
- *Put to other use*: tekstur item yang sama dipakai untuk halo.

**Ide 3 (entity client-side):**
- *Substitute*: bukan entity, tapi render langsung di event.
- *Combine*: entity manifestasi juga jadi entity.
- *Modify*: tanpa AI, tanpa tick server.
- *Eliminate*: hapus collision & interaksi.
- *Reverse*: client tidak pernah魅力的.

### Clustering

- **Klaster A — "Render visual dunia"**: halo ring + manifestasi soul.
- **Klaster B — "Permukaan interaksi"**: struktur GUI Awakening.
- **Klaster C — "Otoritas server & aliran data"**: packet baru, validasi, NBT.
- **Klaster D — "Perluasan gameplay"**: 20 skill baru + efek serangan biasa.

### Convergent

- **Klaster A** → **Opsi 1 (dipilih)**: quad kustom untuk halo (murah, kendali
  penuh atas warna/alpha/rotasi) + item model asli untuk manifestasi (asset
  benar-benar terdaftar, JSON model benar-benar dipakai render).
- Opsi 2 (semua quad kustom): Buang, karena asset model JSON tidak akan
  benar-benar dipakai, sehingga klaim F6 soal aset jadi tidak jujur.
- Opsi 3 (entity client-side): Buang, menambah lifetime/AI/bug tanpa manfaat.

### Keputusan render halo (final)

- Event: `RenderPlayerEvent.Post` (client only), render di dalam pose stack
  pemain yang sama.
- 9 ring = 9 quad datar, tiap quad memakai **satu sprite ring putih** yang
  di-tint per umur → aset texture ring per tier tidak perlu, warna jadi data.
- Susunan: ring di kelilingi pinggang (radius 0.95), sumbu Y di pinggang
  pemain, tiap ring berputar pelan (kecepatan berbeda 4-9°/detik) + bobbing
  sinus 0.06 blok.
- Billboard penuh terhadap kamera → ring terbaca dari segala arah.
- Skala: 0.34 (ring 100 th) → 0.46 (ring 100.000 th) + warna umur.
- Render type: `entityTranslucent` (alpha blend) supaya bisa fade & tint.
- Data umur ring: `List<Integer> ringAges` di capability, disinkron via
  `SyncCultivationPacket` (protocol dinaikkan ke "2").

**Alasan tiap keputusan (R-31):**
- Quad kustom, bukan item render: 9 item render per pemain per frame terlalu
  mahal dan tidak memberi kontrol alpha.
- Tint per umur, bukan 4 texture: warna umur adalah data, bukan aset; 1 aset
  lebih mudah dijaga konsistensinya.
- Billboard penuh: ring datar hanya terbaca dari sudut pandang kamera; model
  3D asli butuh asset 3D yang tidak ada di scope.
- `entityTranslucent`: butuh alpha untuk fade & transparansi tengah ring.

## 2. F2 — Manifestasi Martial Soul

### Keputusan final

- **10 item terdaftar**: `soulland:manifestation_<soul_id>` (masing-masing
  `models/item/manifestation_<soul_id>.json` parent `item/generated` +
  `textures/item/manifestation_<soul_id>.png` 16x16 pixel art).
- Render: `ItemRenderer.renderStatic` memakai model item asli → JSON model
  benar-benar menentukan tampilan, aset terdaftar di registry, texture ada.
- Posisi: 1.9 blok di atas kaki + 1.2 blok di belakang pemain, menghadap kamera.
- Animasi 3 detik: skala 0.15 → 1.25 (materialisasi, ease-out) → 1.25 → 0.35
  (dissipate), plus partikel tematik tiap frame dan satu sound cue saat mulai.
- Fade: skala memendek + partikel yang menyebar + lapisan aura quad translucent
  dengan alpha 0.55 → 0 (fade visual terjadi pada aura, bentuk inti tetap
  terbaca sampai habis).
- Partikel per soul + 1 sound per soul (dari `SoundEvents` vanilla, tanpa aset
  audio baru).

**Alasan:** item model membuat aset "10 model JSON + 10 texture" benar-benar
terdaftar dan dirender (F6 lolos); custom quad untuk aura memberi alpha fade
tanpa asset tambahan.

## 3. F5 — GUI Awakening

### Opsi (divergent)

1. Satu layar: baris tab kategori + daftar soul + panel preview.
2. Wizard 3 layar: kategori → soul → konfirmasi.
3. GUI container ala chest (soul sebagai item slot).
4. GUI gaya buku (cocok dengan buku panduan).
5. Grid 10 kartu soulfull-screen.
6. Selector radial/carousel.

### Convergent

- **Opsi 1 (dipilih)**: satu layar 300x186 dengan tiga zona. Semua informasi
  (kategori, soul, preview, skill, konfirmasi) terlihat tanpa pindah layar →
  tidak ada dead-end, tidak ada state kosong yang tak terlihat.
- Opsi 2 (wizard): butuh 3 layar, menambah langkah, tidak menambah info.
- Opsi 3 (container): mengunci pemain di UI chest, tidak cocok dengan "../upacara".
- Opsi 4 (buku): bagus secara tema, tapi preview panel + tab tidak muat di
  halaman buku.
- Opsi 5 (grid kartu): 10 kartu seragam = monotonic (R-14/R-05) dan tidak
  bisa menampilkan preview kaya.
- Opsi 6 (radial): lambat dipakai, tidak keyboard-friendly.

### Struktur layar

```
┌─ panel tinta 300x186, garis luar batu, garis aksen jade di bawah judul ─┐
│ UPACARA KEBANGKITAN MARTIAL SOUL            (kertas, bold)              │
│ Pilih martial soul yang akan menjadi takdirmu  (redup)                 │
│ ──────────────────────────────── (garis jade 1px)                      │
│ [Alat][Kontrol][Agility][Support][Api][Power][Racun]   (tab, 7 kategori) │
│ ┌ daftar soul ────────┐ ┌ preview ─────────────────────────────┐        │
│ │ ▸ Cangkul Tua       │ │ Cangkul Tua          (warna rarity)  │        │
│ │   Sosis Ajaib       │ │ Common · Alat · Petani biasa        │        │
│ │   Seven Treasure…   │ │ <deskripsi 3-4 baris>               │        │
│ │                     │ │ Panen Raya (1 ring) …                │        │
│ │                     │ │ [ KONFIRMASI ]  (jade)              │        │
│ └─────────────────────┘ └─────────────────────────────────────┘        │
└─────────────────────────────────────────────────────────────────────────┘
```

- Kategori dikelompokkan otomatis dari field `type()` tiap soul.
- Tab memuat label pendek (mis. "Serangan Api" → "Api") agar 7 tab muat di
  300 px.
- Baris soul adalah widget fokus-able (bisa di-Tab, diaktifkan Enter/Space)
  → keyboard penuh (R-32). Tombol KONFIRMASI juga widget.
- Rarity ditampilkan sebagai **nama** + warna, tidak warna-saja (R-25).
- Panel kiri punya state kosong: "Belum ada soul awakened" (R-27).

### Alur & otoritas server

1. Server deteksi pemain belum awakened saat login → kirim
   `OpenAwakeningGuiPacket(mode=AWAKENING)`. **Tidak ada gacha lagi.**
2. Client membuka `AwakeningScreen`, kategori pertama aktif.
3. Pemain memilih soul → panel preview terisi.
4. Pemain menekan KONFIRMASI → client kirim `ChooseSoulPacket(soulId)`.
5. Server validasi:
   - `soulId` ada di `MartialSouls` (tolak id tak dikenal).
   - `!cap.isAwakened()` ( awakenning awal) **atau** `player.isCreative()`
     (mode reroll). Selain itu → tolak + pesan.
6. Server set soul + awakened + level 1 + energy 100, beri buku panduan (hanya
   saat awakenning pertama), sync, dan kirim pesan konfirmasi.
7. `/martialsoul reroll` (Creative) → server kirim `OpenAwakeningGuiPacket(mode=REROLL)`.
   Pada mode reroll judul layar berubah dan soul lama ditampilkan sebagai
   "soul sekarang".

## 4. Packet baru

| Packet | Arah | Isi |
|---|---|---|
| `OpenAwakeningGuiPacket` | S→C | `boolean reroll` |
| `ChooseSoulPacket` | C→S | `String soulId` (maks 64) |
| `SyncCultivationPacket` (diperluas) | S→C | + `int[] ringAges`, `int[] skillCooldowns` (4 slot, sisa detik), `boolean awakened` |
| `ManifestationPacket` | S→C | `int entityId`, `String soulId` → client mulai animasi |
| `ActivateSkillPacket` (diperluas) | C→S | `int slot` (0..3, divalidasi server) |

Protocol channel dinaikkan dari "1" ke "2" karena format sync berubah.

## 5. Perubahan data (NBT) — backward compatible

| Key | Tipe |_default pada save lama |
|---|---|---|
| `awakened` | boolean | sudah ada |
| `martialSoul` | string | sudah ada |
| `level`, `xp`, `rings`, `energy` | angka | sudah ada |
| `gateNotified` | boolean | sudah ada |
| `cooldowns` | compound | sudah ada |
| `ringAges` | **int[] baru** | tidak ada → daftar kosong, lalu di-pad ke jumlah `rings` dengan umur 100 (default paling lemah) |

Save lama **tidak rusak**: `ringAges` yang hilang dibaca sebagai daftar kosong
lalu diisi default sehingga jumlah ring tetap konsisten dengan `rings`.

## 8. Alur render (ringkasan)

| Waktu | Client | Server |
|---|---|---|
| Login | buka `AwakeningScreen` (kalau belum awakened) | kirim `OpenAwakeningGuiPacket` |
| Konfirmasi | kirim `ChooseSoulPacket` | validasi, set soul, sync, beri buku |
| Tekan R/G/X/C | kirim `ActivateSkillPacket(slot)` | validasi ring/energi/cooldown → jalankan skill → kirim `ManifestationPacket` |
| Skill aktif | animasi manifestasi 3 detik + partikel + sound | efek gameplay + partikel server |
| tiap frame | halo ring digambar di `RenderPlayerEvent.Post` | - |
